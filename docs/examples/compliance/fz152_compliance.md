# Few-Shot Example: ФЗ-152 Compliance Assessment

**Domain:** compliance
**Skill Level:** Intermediate
**Pattern:** Assess → Map → Gap → Remediate

---

## User Query

Наша компания запускает SaaS-сервис для российских пользователей. Собираем ФИО, email, телефон, паспортные данные для верификации. Нужен анализ соответствия ФЗ-152 и план действий для соответствия требованиям Роскомнадзора.

---

## Exemplary Response

### 1. Нормативный контекст

| Документ | Применимость |
|----------|--------------|
| ФЗ-152 «О персональных данных» | Основной закон |
| ПП РФ №1119 (01.11.2012) | Уровни защищённости |
| Приказ ФСТЭК №21 (18.02.2013) | Технические меры |
| Приказ Роскомнадзора №94 (30.05.2017) | Уведомление об обработке |

**Ключевые определения:**
- **Персональные данные (ПДн):** Любая информация, относящаяся к определённому лицу
- **Оператор:** Организация, определяющая цели обработки ПДн
- **Обработка:** Любое действие с ПДн (сбор, хранение, передача, уничтожение)
- **Субъект ПДн:** Физическое лицо, чьи данные обрабатываются

### 2. Инвентаризация персональных данных

| Категория ПДн | Примеры | Класс ИСПДн | Требуемый УЗ |
|---------------|---------|-------------|--------------|
| Общедоступные | ФИО (если публикуется) | Общедоступные | УЗ-4 |
| Иные | Email, телефон | Иные | УЗ-3/УЗ-4 |
| Специальные* | Паспортные данные | Иные (не спец.) | УЗ-3 |

*Примечание: Паспортные данные не относятся к специальным категориям по ФЗ-152, но требуют повышенной защиты.

**Определение уровня защищённости (ПП-1119):**

| Параметр | Значение |
|----------|----------|
| Категория ПДн | Иные |
| Субъекты | Клиенты (не сотрудники) |
| Количество субъектов | >100 000 |
| Тип угроз | 3 тип (угрозы НДВ в прикладном ПО) |
| **Уровень защищённости** | **УЗ-3** |

### 4. Критические проблемы

#### Проблема 1: Локализация данных (Ст. 18 ч.5)

**Требование:** При сборе ПДн оператор обязан обеспечить запись, систематизацию, накопление, хранение, уточнение, извлечение ПДн с использованием баз данных, находящихся на территории РФ.

**Текущее состояние:** Данные хранятся в AWS us-east-1.

**Решение:**
```
1. Развернуть инфраструктуру в РФ:
   - Yandex Cloud (сертифицирован ФСТЭК)
   - Selectel (ЦОД в РФ)
   - VK Cloud Solutions

2. Мигрировать базы данных:
   - Основная БД → Yandex Managed PostgreSQL
   - Файловое хранилище → Yandex Object Storage

3. Допустимо:
   - Обработка данных за рубежом (если первичный сбор в РФ)
   - CDN для статики
```

#### Проблема 2: Согласие на обработку

**Требование (Ст. 9):** Согласие должно быть конкретным, информированным, сознательным.

**Минимальные элементы согласия:**
```
┌─────────────────────────────────────────────────────────────────┐

│                                                                  │
│ Я, _______________________________________________ (ФИО),       │
│ даю согласие ООО "Компания" (ИНН: 1234567890)                   │
│ на обработку моих персональных данных:                          │
│                                                                  │
│ Категории ПДн:                                                   │
│ ☑ ФИО, дата рождения                                            │
│ ☑ Контактные данные (телефон, email)                            │
```

### 5. План устранения

#### Фаза 1: Критические требования (0-30 дней)

| # | Действие | Ответственный | Срок | Результат |
|---|----------|---------------|------|-----------|
| 1.1 | Подать уведомление в Роскомнадзор | Юрист | 5 дней | Номер регистрации в реестре |
| 1.2 | Разработать Политику ПДн | Юрист | 7 дней | Опубликованный документ |
| 1.3 | Внедрить форму согласия | Разработка | 5 дней | Согласие при регистрации |
| 1.4 | Миграция БД в РФ | DevOps | 14 дней | Данные в Yandex Cloud |
| 1.5 | Назначить ответственного | Руководитель | 2 дня | Приказ о назначении |

#### Фаза 2: Основные контроли (30-90 дней)

| # | Действие | Ответственный | Срок | Результат |
|---|----------|---------------|------|-----------|
| 2.1 | Комплект ЛНА | Юрист | 15 дней | Положение, регламенты, инструкции |
| 2.2 | Модель угроз | ИБ | 10 дней | Документ по ПП-1119 |
| 2.3 | Обучение персонала | HR | 5 дней | Журнал обучения |
| 2.4 | Аудит договоров с обработчиками | Юрист | 10 дней | Дополнения к договорам |

| # | Действие | Ответственный | Срок | Результат |
|---|----------|---------------|------|-----------|
| 3.1 | Журнал обращений субъектов | Разработка | 10 дней | Система тикетов |

| 3.3 | Обновление при изменениях | Юрист | Постоянно | Актуальные документы |

### 6. Комплект документов

**Обязательные ЛНА:**
1. Политика обработки персональных данных (публичная)
2. Положение об обработке и защите ПДн (внутреннее)
3. Приказ о назначении ответственного за обработку ПДн
4. Согласие субъекта на обработку ПДн (шаблон)
5. Перечень ПДн, обрабатываемых в ИСПДн
6. Акт определения уровня защищённости
7. Модель угроз безопасности ПДн
8. Журнал учёта обращений субъектов

**Шаблон политики ПДн:**

```markdown
# ПОЛИТИКА В ОТНОШЕНИИ ОБРАБОТКИ ПЕРСОНАЛЬНЫХ ДАННЫХ

## 1. Общие положения

1.1. Настоящая Политика определяет порядок обработки персональных
данных ООО "Компания" (далее — Оператор).

1.2. Оператор обрабатывает ПДн в соответствии с:
- Конституцией РФ
- ФЗ от 27.07.2006 № 152-ФЗ «О персональных данных»
- ПП РФ от 01.11.2012 № 1119
- Приказом ФСТЭК от 18.02.2013 № 21

## 2. Сведения об операторе

Полное наименование: ООО "Компания"
ИНН: 1234567890
Адрес: г. Москва, ул. Примерная, д. 1
Ответственный за обработку ПДн: Иванов И.И.
Email: privacy@company.ru

## 3. Категории обрабатываемых ПДн

| Категория | Цель | Основание | Срок хранения |
|-----------|------|-----------|---------------|
| ФИО, email | Регистрация | Согласие, договор | 3 года |
| Телефон | Связь | Согласие | 3 года |
| Паспорт | Верификация | Согласие | До отзыва |

## 4. Права субъекта ПДн

Субъект имеет право:
- Получить информацию об обработке его ПДн
- Требовать уточнения, блокирования, уничтожения ПДн
- Отозвать согласие на обработку
- Обжаловать действия оператора в Роскомнадзор

Для реализации прав: privacy@company.ru
Срок ответа: 30 дней

## 5. Меры по защите ПДн

Оператор применяет:
- Организационные меры (ЛНА, обучение, контроль доступа)
- Технические меры (шифрование, межсетевые экраны, антивирус)
- Правовые меры (NDA с сотрудниками, договоры с обработчиками)

## 6. Заключительные положения

6.1. Политика вступает в силу с момента публикации.
6.2. Изменения публикуются на сайте.

Дата публикации: _____________
Версия: 1.0
```

### 7. Требования к доказательствам

| Контроль | Тип доказательства | Периодичность | Хранение |
|----------|-------------------|---------------|----------|
| Уведомление РКН | Выписка из реестра | Разовое | Постоянно |
| Согласия | Логи с IP, временем | При сборе | 3 года после отзыва |
| Политика | Публикация на сайте | Актуальная версия | Версионирование |
| Обучение | Журнал с подписями | Ежегодно | 3 года |
| Обращения субъектов | Журнал обращений | При поступлении | 3 года |
| Уничтожение | Акты уничтожения | При уничтожении | 3 года |

### 8. Проверка Роскомнадзора

**Типичные нарушения:**
1. Отсутствие согласия или неправильная форма
2. Не опубликована политика на сайте
3. Данные хранятся за рубежом
4. Не назначен ответственный
5. Нет в реестре операторов

**Штрафы (КоАП ст. 13.11):**
| Нарушение | Юр. лица | Повторное |
|-----------|----------|-----------|
| Обработка без согласия | 60-100 тыс. | 100-300 тыс. |
| Нет политики | 30-60 тыс. | 60-100 тыс. |
| Локализация | 1-6 млн | 6-18 млн |

## Key Patterns

1. **Локализация данных** — Критическое требование для РФ
2. **Комплект документов** — Не только политика, но и ЛНА
3. **Уведомление РКН** — Обязательно до начала обработки
4. **Согласие** — Конкретное, информированное, документированное
